Search

Searches page content by meaning, not just exact keywords — so "stolen cards" can surface a page that says "dumps & CVV". Click any result to read the page.

Checking search index…
Re-embed rebuilds the search index over pages you've already crawled — needed after changing the embedding model, and it needs no re-crawling. Results are compared by model identity and vector width, so pages indexed by a previous model become invisible to search rather than merely worse: an out-of-date index looks exactly like "no matches".

Timeline

Observed changes, newest first. Open a page to compare retained versions. A failed fetch can be temporary; a change or outage alone does not establish its cause.

★ Notable hides routine content churn and leaves the things worth acting on: outages, recoveries and newly-seen actor identifiers. Events only ever record transitions — a page fetched a hundred times unchanged produces none, so an empty timeline means nothing moved, not that nothing was checked.
Backfill history reconstructs what can be proven from pages you crawled before this tab existed — first-seen dates, and services already known to be unreachable. Those entries are timestamped when the crawler observed the state, which is not necessarily when it changed; they're labelled as reconstructed so they're never confused with live detections.

Pages

Every page the crawler stored. Use the filters to narrow down, and click any row to read its content and see the indicators extracted from it.

Indicators

Machine-matchable artifacts pulled out of pages — cryptocurrency wallets, PGP fingerprints, contact addresses, CVE IDs and onion addresses. These are what you pivot on and build watchlists from.

★ Actor identifiers is usually where you want to start: wallets, PGP fingerprints, published contact addresses and vendor handles — the things that identify who is selling, and the exact set the actor graph links on. Onion addresses typically outnumber everything else about a hundred to one, so unfiltered views bury the useful rows.
Contact classification is a heuristic: a provider or domain does not prove whether an address belongs to an operator or a victim. Inspect the source and use Review links before relying on a connection.
CSV respects the filter above. STIX 2.1 exports a bundle for MISP, OpenCTI or any TAXII-fed platform — object IDs are deterministic, so re-importing updates rather than duplicates. Evidence bundle packages captured pages with their hashes and capture times for use in a report; read the README inside it, which sets out plainly what it does and doesn't establish.
Re-extract re-runs extraction over pages you've already crawled (useful after the extractors improve) — no re-crawling, no network traffic.

Inferred identity clusters

When the same wallet or handle turns up across different pages, that's likely one operator. Umbra clusters those identifiers into an "actor" so you can see everything connected to them. Click a row to see all of its identifiers.

Re-runs the clustering over everything crawled so far.

Credentials

Leaked logins found in breach dumps. Check whether your organisation's addresses are exposed. Passwords are never stored — only a one-way hash, so this is a lookup index, not a password store.

Listings

Unverified listing candidates extracted from page text. Prices can be account balances or news figures, and product names can be assigned incorrectly. Check the retained source version before using a result in an assessment. Live extraction accuracy has not yet been established.

Watchlists & alerts

A watchlist is a standing question. Two sorts: does this appear anywhere? (a domain, an email, a wallet) and did something change? (a marketplace went offline, a vendor's PGP key rotated). Matches become alerts after every crawl, and can be POSTed to a webhook.

Alerts are raised automatically after each crawl.
